SLIDE 3 // ARCHITECTURAL FLOW 3 / 5

Multi-Tiered Decoupled Pipeline

Raw packets flow from Npcap into a 10k bounded queue, pass through the parsers and classifier, and can inform outbound IPv4 WFP rules in protect mode.

1. Producer Tier

Npcap / PCAP callback directly pushes raw packets into the SPSC circular ring buffer.

2. FastPath & DPI Tier

Known flows hit 5-tuple hash table (O(1)). New flows undergo TLS SNI, QUIC, and DNS parsing.

3. Kernel & Dashboard Tier

Injects WFP kernel filters and exports atomic JSON metrics to Node.js / Web UI every 500ms.

🛡️ Viva Defense & Cross-Questioning Guide

PERFORMANCE Q1: Why did you build this in C++ instead of Python (Scapy) or Go?
Why C++17: The analyzer parses packet bytes directly and uses a bounded producer-consumer queue. Its measured offline throughput is documented in BENCHMARK.md; live capture capacity and loss still need separate testing.
ENCRYPTION Q2: HTTPS is encrypted. How can you inspect what website is being visited without SSL keys?
Key Defense: During the initial TLS handshake, before symmetric encryption is negotiated, the client sends a plaintext ClientHello packet containing the Server Name Indication (SNI) extension. Our DPI engine directly parses the TLS record layer to extract the requested hostname. We also passively snoop on DNS query/response packets to correlate IP addresses with domain names in real time.
MODERN PROTOCOLS Q3: What if the client uses TLS 1.3 with ECH (Encrypted Client Hello) or DoH (DNS over HTTPS)?
Key Defense: When ECH or DoH is enabled, our engine falls back to multi-layer heuristics: (1) QUIC Initial packet inspection, which often leaks the SNI prior to handshake completion, (2) Destination IP Autonomous System (AS) and IP block mapping, and (3) Flow fingerprinting based on packet size distributions, burst timing, and port heuristics.
OPTIMIZATION Q4: How does your FastPath caching make the engine faster?
Key Defense: A single connection stream contains thousands of data packets, but its protocol identity is established in the first 1–3 packets (SYN/ClientHello). Our FastPath maintains an O(1) 5-tuple hash table (src_ip, dst_ip, src_port, dst_port, protocol). Once a flow is marked CLASSIFIED, subsequent packets skip the DPI parsing engine entirely and are forwarded immediately.
SECURITY & OS Q5: What is WFP, and why is kernel blocking superior to user-space blocking?
Key Defense: WFP (Windows Filtering Platform) is Microsoft's kernel-level network filtering driver architecture. User-space blocking only drops packets after the OS has already spent CPU cycles on hardware interrupts, packet reassembly, and socket processing. WFP filters block packets directly inside the kernel network driver stack at Layer 3/4 with zero user-space latency.
FAIL-SAFE Q6: If your engine crashes or terminates, will the user's internet remain blocked?
Key Defense: No. We register a Dynamic WFP Session using FWPM_SESSION_FLAG_DYNAMIC. The Windows kernel automatically garbage-collects and removes all registered filters the exact moment our process handle terminates or crashes, guaranteeing total fail-safe operation.
BURST HANDLING Q7: How do you handle sudden packet bursts under high network traffic?
Key Defense: We decouple packet ingestion from inspection using a dedicated Producer thread with an atomic single-producer single-consumer ring buffer (capacity: 10,000 packets). Telemetry tracks capture_drops and processing_drops in real time on the dashboard to ensure zero silent data loss.
